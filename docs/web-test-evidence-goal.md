## Outcome

External model evaluation now binds completion statistics to a hash-verified model-sourced planning receipt. The evaluator records the generated Charter summary and exact Charter hash, rejects missing or host-sourced planning evidence, and keeps pre-existing-state and independent-reader gaps separate from model completion. The out-of-tree smoke passes with one evidenced completion, one explicit reader gap and one pre-existing-state stop; this is an evaluator-integrity milestone, not unfamiliar-production-app certification.

Mission execution now has a pre-execution planning admission gate. When a newly assessed plan carries one of the execution-blocking `planning.evidenceGaps` (`business-oracle`, `surface-assertion`, `surface-selector`, or `surface-page`), approval does not authorize product actions: the Mission is persisted as `blocked`, records an evidence-boundary `firstFailure`, and reports that no product tool was invoked. Coverage-only gaps such as an incomplete project map or unmeasured whole-project workflow coverage do not suppress a declared Charter run; they remain visible and can make the final result `inconclusive`. This is intentionally narrower than treating every legacy `missingInputs` note as a blocker, so older deterministic Charters remain readable and runnable under their existing runtime gates. The CLI plan-review path remains the user-facing place to resolve the gap and create a new reviewed plan.

This gate is a safety boundary, not proof that a plan is complete. A Mission with no explicit planning gap can still become `inconclusive` or `blocked` when environment, authentication, target binding, action execution, independent business reads, or evidence integrity are not established. Acceptance must verify both the preflight state and the final evidence report.

Given a supported Web target, a developer's test intent, and the necessary access and expected outcomes, ProofKit should produce a reviewable test plan, execute it against the real application, and deliver a report that shows each observed action and the evidence supporting each conclusion. The same contract should apply to unfamiliar applications without adding application-specific branches to the runner.

This is an acceptance goal, not a claim that an address and a vague intent can establish unknown business rules. Missing expectations, credentials, environment access, or independent business observations must remain explicit gaps. UI observations must not be reported as proof of persistence or business correctness.
